# P09 — Rung 14.3 execution (loop 140)

Track `invariance`. The upgrade itself.

## Preconditions
Loop 130 green. A fresh snapshot taken immediately before this loop.

## Steps
1. `ddev typo3 extension:setup` — the Core command that performs the schema migrations.
2. Review schema changes **before** applying: the backend database analyzer in Admin Tools, or
   `database:updateschema "*.add,*.change" --dry-run` **only** where the project already ships
   `helhum/typo3-console` — that command is not Core.
3. `ddev typo3 upgrade:list`, then the reviewed `upgrade:run` steps.
4. `referenceindex:update`, `language:update`, then `cache:flush` and `cache:warmup`.
5. Log in to the backend at the DDEV URL. Work through Admin Tools environment and upgrade status,
   the database analyzer state, and the remaining wizard list until clean.

## The warm-up deprecation is not noise
Cache warm-up must not emit the #108345 package-metadata deprecation. When it does, fix the
extension's `composer.json` (`version` / `providesPackages`) rather than ignoring the message — v15
stops evaluating `ext_emconf.php` entirely, and this is the warning that the metadata is not where it
needs to be.

## Exit
Schema comparison clean. Every wizard run, or consciously skipped with a recorded reason. Warm-up
emits no #108345 deprecation.

## Blocking
Any failure — restore the snapshot, fix the cause, rerun. Never continue on a half-migrated database.
